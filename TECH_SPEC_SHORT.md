# IshMed — шпаргалка на одну страницу

Подробности — в `TECH_SPEC.md`. Обновлено 2026-08-16, после этапа двуязычия.

## Стек

**Python 3.14** везде на бэкенде. FastAPI + uvicorn (кабинет клиники), aiogram 3.30 (два Telegram-бота), psycopg 3.2 с async-пулом, pydantic-settings, argon2 на пароли, segno на QR. **PostgreSQL 18.6 + pgvector.** Фронтенд — React 19, TypeScript, Vite 8, Tailwind 4, TanStack Query. Одна Azure VM, nginx + systemd, без докера. 33 миграции, 154 теста.

## Три поверхности, все работают, все двуязычные

- `@ishmedsifatbot` — пациент по QR оставляет отзыв: оценка, текст, голос, фото.
- Веб-кабинет — клиника: структура, штат, отзывы, QR, вакансии с авто-интервью.
- `@ishmedbot` — медик: витрина вакансий, отклик по deep link, интервью голосом.

Русский и узбекский на всех трёх. Язык — свойство человека: лежит в `product.users.locale` и общий для бота и кабинета.

## Где AI — четыре живых деплоймента

| Модель | Задача | Замерено |
|---|---|---|
| `gpt-5` | разбор текста вакансии, план вопросов, саммари интервью | 2.2 / 3.8 c |
| `gpt-5-mini` | «ответ по делу или уточнить» | 1.2 c |
| `gpt-4o-transcribe` | расшифровка голоса | 1.2 c |
| `tts` | озвучка вопроса | 0.9 c |

Каждый вызов пишется в `ai.model_calls` с задержкой и токенами. Отсюда стоимость **посчитана, а не оценена: интервью $0.0053 текстом, $0.0076 с голосом** — на $5000 порядка 660 000 интервью.

Голос замкнут в обе стороны: Telegram отдаёт ogg/opus, Azure принимает напрямую, `tts` тоже отдаёт ogg/opus — ffmpeg не нужен нигде.

**Узкое место одно и оно жёсткое:** квота `tts` — 3 запроса в минуту на всю подписку, поднять нельзя. Поэтому озвучка вопроса кэшируется в `job_questions.voice_file_id`: один вызов на вопрос за всю жизнь вакансии вместо одного на кандидата.

`reasoning_effort=minimal` обязателен: с рассуждением по умолчанию `gpt-5` отвечает 10.2 c вместо 2.3 c, и трёхминутное демо рассыпается.

## Где LangGraph

**В коде нет, и это ответ, а не оправдание.** Интервью оказалось детерминированным автоматом: порядок вопросов фиксирован планом, состояние уже лежит в `interviews` и `interview_turns`. Чекпоинтер дал бы второй источник правды и риск расхождения без выигрыша. Практическое следствие: **бота можно перезапустить посреди разговора**, человек продолжит с того же места.

Граф станет оправдан на ветвлениях — разных линиях вопросов по ответам. Схема `agent` под чекпоинты уже стоит.

## Главное решение: гарантии в базе, а не в коде

Решение о том, какие данные запросить, принимает LLM. Код можно уговорить промптом, `REVOKE` уговорить нельзя.

**Контакты кандидата закрыты правами.** `REVOKE ALL ON candidate_contacts` — ни одного права у прикладной роли. Все четыре, а не только SELECT: запрет на чтение обходится через `UPDATE ... RETURNING`. Единственная дверь — `SECURITY DEFINER` функция, требующая принятого приглашения и обязательно пишущая в журнал согласия.

**RLS на 27 таблицах, 32 политики.** Контекст ставится через `set_config(..., is_local => true)` — живёт до конца транзакции и не течёт между запросами из пула. Не выставленный контекст означает «ничего не видно», а не «видно всё». Неизвестная роль **уменьшает** права.

**Бизнес-правила как ограничения БД.** Матч без двух объяснений физически невозможно записать. Открытый пароль не пройдёт даже транзитом через аргумент функции. «Вакантно/занято» — генерируемая колонка. Правильный ответ в тесте закрыт колоночным грантом.

**Модель не управляет диалогом интервью.** Вопросы выдаются из одобренного менеджером плана строго по порядку — иначе двух кандидатов нельзя сравнить. Предел ходов считает база. Переиграть нельзя — уникальный индекс. Решение о найме принимает человек, промпт саммари запрещает вердикт прямым текстом.

## Двуязычие — инженерная задача, а не файл с переводами

Дырка в переводе не ломает приложение: оно молча падает на русский, и узбекоязычный человек получает русскую фразу посреди узбекского диалога. Заметит зал. Поэтому полнота держится машиной: тест сверяет паритет ключей **и подстановок** `{...}`, а на фронте узбекская таблица типизирована по русской — забытый ключ не собирается.

Не переводятся вопросы плана: их одобрил менеджер, а подменять одобренное машинным переводом значит лишить кандидатов сравнимости. Уточнение модель пишет на языке кандидата, саммари — на языке клиники.

Русский требует трёх форм и падежей («опыт от 3 **лет**», не «от 3 года»), узбекский — одной. Обе ошибки согласования поймал тест, а не глаз.

## Что решали и как

**Отказались от векторного поиска в матчинге.** В каталоге было 1305 врачебных названий против 54 медсестринских, 24:1. Семантический поиск на таком распределении ставит врача выше медсестры на вакансию медсестры. Категория роли — hard constraint, не предпочтение. Матчинг детерминированный.

**Снесли импортированный каталог** — 3595 вакансий с госпортала. Не парсим никого. Сносили не `DROP SCHEMA CASCADE`: одиннадцать триггеров вызывали функцию из удаляемой схемы, каскад снёс бы их молча, и `updated_at` тихо перестал бы обновляться. Триггеры перевесили перебором по `pg_trigger`.

**Оценку ответа увели на mini.** Журнал показал 156 вызовов простой задачи на старшей модели. Видно только потому, что есть журнал.

**Long polling, а не webhook.** DNS-зона рассинхронизирована между NS. Завязывать доставку апдейтов на резолвинг домена нельзя.

**Публичная страница отзыва — серверный HTML, а не React.** Пациент открывает её на мобильном интернете в коридоре.

**QR рисуется на лету, без записи на диск.** Slug — 12 символов из алфавита без похожих глифов.

**Тесты идут против живой PostgreSQL.** Половина того, что проверяется, — права, RLS и ограничения БД; на моках они всегда «работают». Подготовка данных под владельцем, проверки — под урезанной ролью.

## Долги — назвать самому

`course_answer_key()` не проверяет роль менеджера, сотрудник достаёт ключ ответов (закрывается одной строкой) · политика на профилях кандидатов не переписана под роли · `attach_to_review()` не проверяет право на конкретный отзыв · курсы, матчинг и приглашения есть в базе, API и UI нет · профиль кандидата не дополняется из интервью · CI нет, `make verify` руками · узбекский не вычитан носителем (полнота гарантирована, формулировки — нет) · токен бота утёк в переписку, нужен `/revoke`.
