**Назначение:** только факты; не roadmap.

## Готово

- Название `IshMed` и домен `ishmed.uz`.
- PostgreSQL 18 работает.
- Применены 10 миграций `001–010`.
- Существуют схемы `raw`, `core`, `ai`.
- В `core`: 3 595 вакансий и 773 организации.
- Для 3 595 вакансий рассчитаны embeddings.
- Работает CLI-поиск vector + FTS + RRF.
- Azure: доступны deployments `gpt-5` и `text-embedding-3-small`.
- Готов статический pitch-site: главная, Clinics, Pilot, Medics.

## Не готово

- Telegram-бот.
- Speech-to-text: отдельного deployment/provider сейчас нет.
- Транзакционная продуктовая схема кандидатов, клиник, вакансий, match и consent.
- Голосовой intake и подтверждение профиля.
- Rules-first matching candidate ↔ vacancy.
- Приглашение, согласие и защищённое открытие контактов.
- Автоматические тесты P0 и resettable demo state.

## Важные границы

- `core.vacancies` — импортированный каталог. Новые вакансии клиник хранятся отдельно с UUID.
- Текущий semantic search не является P0 matching: контрольный тест поднимал нерелевантные врачебные роли выше процедурной медсестры.
- Внутренние названия `ezgumed` в БД/Azure до хакатона не переименовывать.
- Реальные персональные данные без согласия не использовать.

## Следующий результат

Рабочий Telegram happy path:

`/start → роль → голос медика → подтверждение профиля → вакансия клиники → объяснимый match → приглашение → принятие → контакт`.
