# IshMed — рабочие документы

Здесь находится только актуальный контур продукта. Исходный research лежит в `../research/` как архив: Claude не должен использовать его как техническое задание.

## Что читать Claude

Читать строго в этом порядке:

1. `01_product/CLAUDE_START_HERE.md` — одна стартовая команда.
2. `01_product/P0_BUILD_PLAN.md` — единственный источник P0-задач и критериев готовности.
3. `00_CURRENT_STATE.md` — что уже реально существует в коде и инфраструктуре.

`00_MASTER_PLAN.md` объясняет продуктовые решения. Остальные папки относятся к pitch, demo и проверке бизнеса; они не задают инженерный scope.

## Приоритет документов

Если формулировки расходятся:

1. `P0_BUILD_PLAN.md` определяет, что кодить сейчас.
2. `P1_ROADMAP.md` определяет, что запрещено затягивать в P0.
3. `00_CURRENT_STATE.md` определяет факты.
4. `00_MASTER_PLAN.md` определяет стратегию.

## Рабочие зоны

- `../Source/` — инженерная реализация Claude.
- `../pitch-site/` — готовый статический pitch/landing сайт.
- `../research/` — архив исследований, не инструкция.
- `02_pitch/`, `03_demo/`, `04_validation/`, `05_brand/` — материалы Codex для презентации и пилотов.
